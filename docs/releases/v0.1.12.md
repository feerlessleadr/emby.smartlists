## v0.1.12

**New: phone alerts for the Embidextrous Android app**

- The plugin now sends alerts to the administrator sessions that are connected to Emby (the app listens for them): `SmartLists.RefreshFailed` when a list could not be refreshed (at most one alert per list per hour, lists that fail together make one alert), `SmartLists.RefreshRunFinished` after a "Refresh all" or a scheduled batch, and `SmartLists.TimerStopped` when scheduled refreshes have stopped running.
- A new **Phone alerts** section on the Settings tab has a master switch and one switch per alert. Failed refreshes and a stopped timer are on by default; the run summary is off. An alert that is switched off is neither sent nor logged.
- The app subscribes on Emby's websocket (`SmartListsEventsStart`, answered with `SmartListsEvents`: events since the number the app gives, new events within about a second, and a heartbeat every 30 seconds; administrators only; the app sends its administrator token inside the start message and the plugin checks it with Emby's session manager, because Emby does not identify the user of a header-authenticated socket), because Emby's session push does not reach a websocket that keeps its token in a header.
- Alerts never contain file paths, drive letters or share names.
- An app that missed an alert can ask for it: `GET /Plugins/SmartLists/Events?After=<number>` returns the last 500 alerts, and `GET /Plugins/SmartLists/Notifications/Catalog` describes them. `GET /info` also reports `ApiLevel` and `Features`.
- The API version stays 1: only properties and calls were added. Details and sample messages: `docs/notifications.md`.

Nothing existing changed; lists and refreshes behave as before.

Upgrade note: replace the single `Emby.Plugin.SmartLists.dll` and restart Emby.
